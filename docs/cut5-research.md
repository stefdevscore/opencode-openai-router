# Cut 5 research: model evidence and classification

Status: research and proposed sequence, not an implemented ranking policy. Investigated 28 October 2026 against OpenCode 2.2.0. No connected account or paid inference was used.

## Recommendation

Use a versioned, evidence-first pipeline with automatic, optimistic recovery. The catalog remains the authority on what the host exposes; it does not establish coding quality or account entitlement. First collect and validate public, attributable evidence. Compare measured results only when identities, benchmark version, settings and agent conditions are genuinely comparable. When evidence is incomplete, use an evaluated, clearly labeled provisional estimate rather than pretending it is a measured result. Host availability and safety constraints still apply.

Use an LLM primarily as an **evidence extractor**, not an oracle that invents measured rankings. It may identify claims and their exact source passages in bounded public material, or produce separately labeled provisional estimates when comparable evidence is unavailable. Code checks attribution and structure; semantic correctness and the usefulness of provisional estimates require independent evaluation. A schema-valid answer can still be wrong. Direct structured source adapters should avoid inference altogether when they provide sufficient evidence.

There are two different anchors:

- **Comparison anchor:** an exact, versioned model-and-configuration result in the same evaluation series and harness. Compare new candidates against it only when the source supplies comparable evidence. The anchor is not a hard-coded model role and does not establish a global quality score. If the anchor disappears, coverage changes or methodology changes, invalidate the comparison rather than invent a replacement.
- **Extractor anchor:** a replaceable host-available model and variant evaluated against a frozen, independently labeled test set. Record its exact identity, variant and prompt/schema version. Do not choose one at random or treat self-assessment as independent validation. If it retires or fails, automatically test a replacement only when new-model work actually needs inference; there is no periodic classifier-only call. Attempts use automatically renewing limits. During an actual outage or a spent limit, resume eligible pending new-model work when conditions recover and retain prior results; do not duplicate an issued request with an unknown outcome; never claim a call succeeded when it did not.

One extractor can process a bounded batch of newly discovered models in one invocation; multiple new models do not each require multiple stages of model calls. Normal refreshes, changes to known models and periodic checks must not invoke classification. Compare direct extraction with a model-assisted path on the same frozen evidence packets before adding a second model or an escalation pass. Additional verification should be deterministic where possible; only add inference when measured benefits justify its usage and the automatic rolling limit allows it.

## Evidence sources and constraints

- OpenCode's 2.2 `model.list` and provider/integration APIs provide the host-effective identifiers, availability view, capabilities, limits and variants. The implementation in [catalog](specs/catalog.md) records these as host facts; it cannot derive a coding-quality order.
- [OpenAI model comparison](https://developers.openai.com/api/docs/models/compare) supplies provider-reported guidance and API pricing, not independently verified coding-task outcomes or ChatGPT subscription consumption. Automatically acquiring and mapping a new model's exact official identity and source document is not yet proven.
- [SWE-bench experiment entries](https://github.com/SWE-bench/experiments) have structured metadata and public submission artifacts. The [Verified leaderboard](https://www.swebench.com/verified.html) includes different agents and methods; its bash-only view controls the agent better, but compatibility, model identity and configuration must still be checked. OpenAI has [raised concerns about SWE-bench Verified](https://openai.com/index/why-we-no-longer-evaluate-swe-bench-verified/), including benchmark contamination and test quality, so it is not a standalone ground truth or release gate.
- [Artificial Analysis](https://artificialanalysis.ai/data-api) publishes structured identity, benchmarks and performance, but its API needs a key; free access is internal-use only and redistribution restrictions apply. Coverage, exact identity mapping and licensing for this plugin have not been established. Do not bundle or silently scrape its data or require it for v0.1.

The preliminary OpenAI index adapter fetches the fixed public Markdown index with a byte cap and exact model-path matching, without sending model IDs or credentials. A live, credential-free check matched three explicit public IDs and excluded an absent ID. This is provider-authored descriptive evidence, not a benchmark or proof of universal coverage; legal/terms review, real host canonical-identity mapping, caching and automatic refresh remain open. A source requiring a new key, restrictive redistribution, ambiguous aliases, missing model/variant configuration or incompatible benchmark conditions cannot silently become the default. Provider claims and third-party measurements remain separately attributed. Evidence text is untrusted and cannot override plugin instructions or executable code.

## OpenCode transport findings

The pinned SDK exposes `ctx.experimental.generate.text({ model, prompt })`; its response contains `{ text }` only. The pinned source uses a stateless generator without a stored session and applies `ModelRetry.retryOneShot`, which can retry certain errors internally. The [2.2 local probe](../scripts/probe-v2-classifier-transport.mjs) invokes it through a fixture plugin and loopback provider: one observed local provider request returned text, created no session messages and did not change the existing session selection. It does not verify ChatGPT/OAuth compatibility, token metering, cancellation after dispatch, hidden retry accounting, strict output schemas or account allowance.

The currently pinned API input has no per-call output token cap, schema or usage fields. Thus a plugin can cap **its own dispatch count and input size**, but cannot honestly promise an exact token, currency or subscription-allowance ceiling on this path. Host retries make a plugin-level call count distinct from provider attempts. Timeout is a wait limit, not proof that an already-issued request stopped or consumed no allowance. A keyed OpenAI API transport is a separate product/billing integration, not a substitute using ChatGPT credentials; it is out of scope unless explicitly configured and authorized.

## Proposed cut 5 sequence and QA

1. **Source and identity spike:** implement and test one permissible structured source with bounded retrieval, exact mapping and provenance; audit actual coverage across a frozen sample of current/new/removed/ambiguous models. If no source qualifies, document the gap and evaluate provisional estimation. No model usage in this spike.
2. **Evidence store and cache:** versioned fingerprints, bounded storage, deduplicated refresh, backoff, expiry, offline recovery and invalidation on source or catalog changes. Tests use frozen public or synthetic fixtures. No classifier calls.
3. **Extractor evaluation:** freeze independently reviewed evidence packets and expected supported claims, including misleading content, alias collisions and unknown cases. Compare deterministic parsing and one or more available extractor candidates. Measure unsupported claims, identity errors, abstention, coverage and usage; retain a held-out set. One calibrated extractor is preferable to random or multi-model voting.
4. **Automatic host transport:** credential-free isolation, failure, recursion and retry tests first; a separately authorized synthetic real-account check later. Use a conservative, automatically renewing invocation limit and clearly disclose metering limitations; a dispatch count is not a hard spending or token cap. Recover automatically after temporary exhaustion or failure.
5. **Ranking acceptance:** distinguish grounded, comparable evidence from explicitly provisional estimates; validate both extraction and actual routing outcomes with the frozen paired coding corpus. Quality, latency and total usage are separate outcomes. Do not present unsupported estimates as measured facts.

[OpenAI evaluation guidance](https://developers.openai.com/api/docs/guides/evaluation-best-practices) recommends testing model judges against human labels and notes position and verbosity bias. This supports calibrating an extractor and independently validating routing outcomes; it does not prove any particular extractor is suitable. OpenAI's [structured output documentation](https://developers.openai.com/api/docs/guides/structured-outputs) also documents refusals and incomplete responses. The OpenCode 2.2 one-shot text interface does not itself expose that structured-output contract, so local JSON validation and fail-closed behavior remain necessary.
