# OpenCode 2.2 catalog readiness investigation

Investigation of pinned OpenCode commit `1097e2668b1e08ad63bdf0b1c4860b9bc01e420c`. No live account or inference was used.

The [model-list handler](https://github.com/anomalyco/opencode/blob/1097e2668b1e08ad63bdf0b1c4860b9bc01e420c/packages/server/src/handlers/model.ts) waits for plugin activation, then returns `Model.available()`. The [model service](https://github.com/anomalyco/opencode/blob/1097e2668b1e08ad63bdf0b1c4860b9bc01e420c/packages/core/src/model.ts) builds a snapshot from provider inputs and returns enabled chat models by default. This supports treating the result as a view of currently materialized host models; it does not establish that the provider's upstream data is current or that the account is entitled to every model.

The [models.dev source](https://github.com/anomalyco/opencode/blob/1097e2668b1e08ad63bdf0b1c4860b9bc01e420c/packages/core/src/models-dev.ts) first uses a configured file, cached catalog or bundled snapshot, and separately schedules background refresh. Its model decoder can skip entries it cannot understand. The [provider plugin](https://github.com/anomalyco/opencode/blob/1097e2668b1e08ad63bdf0b1c4860b9bc01e420c/packages/core/src/plugin/models-dev.ts) applies refreshed data after startup. Thus plugin activation or a valid, nonempty response does not by itself prove the first list reflects all models already published at installation time. A newly *observed* host model may have existed before the initial snapshot. This is a source-based inference about the possible lifecycle, not a measured failure rate or proof of behavior for every OpenAI account.

The plugin SDK does not provide an established freshness/completeness signal for this distinction in the inspected model interface. The current `CatalogStore.complete` means the returned entries parsed consistently; it is not a host readiness assertion. The evidence adapter therefore requires a separately established completeness guarantee and remains unregistered. Time delays or repeated identical lists alone cannot prove that a background refresh has finished successfully.

## Next verification

The [packed baseline fixture](../../scripts/probe-v2-baseline.mjs) ran inside OpenCode 2.2. It used host `model.list` with simulated list stages, a simulated connected status, public index and classifier. Baseline and the later appearance of a public model already present in the initial source caused no generation; a subsequently added synthetic public model caused one fake generation; reopening the pipeline caused no further generation. No provider request occurred and the session stayed unchanged. This is not a real models.dev refresh, live account test or proof of upstream completeness.

The unregistered prototype now stores hashes of public IDs present at baseline and suppresses classification if a host model exposed later maps to one of them. Local tests cover missing/malformed source, alias resolution, restart and late matching. A direct fetch of the [public OpenAI index](https://developers.openai.com/api/docs/models.md) during this investigation returned 102 parseable IDs; that count does not establish coverage of the OpenCode catalog or ChatGPT subscription models.

**Unresolved:** The published index can omit a model that already existed. If that model appears in both the public index and host catalog later, the plugin cannot determine from those observations alone whether it was created after baseline or merely omitted earlier. The inspected host interface also does not prove that an account/connection change retains the same catalog namespace. Neither repeated identical snapshots nor elapsed time resolves those ambiguities. Accordingly the fixture's explicit `authoritativeCatalog: true` is synthetic; the production adapter must not claim this verification passed or activate paid classification based solely on parse completeness. Test an actual older bundled/cached snapshot followed by real refresh and investigate a supported refresh/source-version signal or authoritative release dates. Record index-to-connected-catalog coverage without exposing account identifiers.

## Accepted operating definition

The user accepted first-observed-after-baseline semantics. A model need not be proven globally new; a previously omitted older model can be assessed once. Global publication-time completeness is therefore no longer required for baseline activation. Current snapshot integrity, source mapping, freshness and durable identity deduplication remain requirements. The public-index baseline suppresses known pre-existing IDs as an efficiency measure.
